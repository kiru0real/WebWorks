## 📌 О проекте

**NexoraCRM** — самостоятельная full-stack CRM-платформа для небольших и средних команд. Система не привязана к конкретной отрасли: её можно адаптировать под агентство, студию, B2B-компанию, консалтинг или отдел продаж.

Цель проекта — собрать основные процессы взаимоотношений с клиентами в одном рабочем пространстве: от первого контакта до закрытия сделки и дальнейшей работы с клиентом.

## ✨ Возможности

### Dashboard
- KPI: контакты, открытая воронка, выручка успешных сделок и конверсия.
- График фактически закрытой выручки (по дате перехода в «Успешно») и распределение сделок по этапам.
- Последняя активность команды.
- Ближайшие задачи и быстрые действия.

### Контакты
- Создание, просмотр, редактирование и удаление контактов.
- Компания, email, телефон, источник, статус и потенциальная ценность.
- Теги и поиск по имени, компании, email и телефону.
- Табличный и карточный режимы.

### Сделки
- Kanban-воронка с шестью этапами: новая, квалификация, предложение, переговоры, успешно и отказ.
- Перемещение карточек между этапами drag-and-drop.
- Быстрое изменение этапа через список в карточке.
- Сумма, вероятность закрытия, контакт и дата закрытия.

### Задачи и календарь
- Создание задач с описанием, приоритетом, сроком и связанным контактом.
- Статусы: к выполнению, в процессе и завершено.
- Календарь с задачами по датам и повесткой на ближайшее время.

### Отчёты
- Выручка успешных сделок по месяцам (по фактической дате закрытия).
- Структура воронки и объём на каждом этапе.
- Источники контактов.
- Топ клиентов по сумме связанных сделок.
- Печать / экспорт через системный диалог браузера.

### Команда и доступ
- Роли: администратор, руководитель и менеджер по продажам.
- Создание аккаунтов сотрудников.
- Отключение и повторная активация учётных записей.
- Серверная проверка прав доступа.

## 🧱 Технологический стек

| Слой | Технологии |
|---|---|
| Frontend | React 19, TypeScript, Vite 8 |
| UI | CSS, Lucide React, адаптивная вёрстка |
| Backend | Node.js 22+, Express 5 |
| Database | SQLite через `sql.js` (WebAssembly) |
| Auth | bcryptjs, серверные сессии, HttpOnly cookie |
| Security | Helmet, ограничения JSON body, параметризованные SQL-запросы |

### Почему SQLite через WebAssembly?

Для локальной разработки и портфолио не требуется отдельно устанавливать PostgreSQL или собирать нативный SQLite-модуль. `sql.js` работает через WebAssembly, а сервер сохраняет SQLite-файл в `data/nexora.sqlite` после операций записи.

Это намеренно простой вариант для локального запуска и небольших демонстрационных нагрузок. Для крупной многопользовательской production-системы лучше перейти на PostgreSQL и полноценный механизм миграций/резервного копирования.

## 🚀 Запуск на Windows

Требуется **Node.js 22.12+** и npm. На Node.js 24 проект также рассчитан.

1. Распакуй архив и открой папку `nexoracrm` в VS Code.
2. Создай локальный файл настроек:

```powershell
Copy-Item .env.example .env
```

3. Установи зависимости:

```powershell
npm install
```

4. Запусти frontend и backend:

```powershell
npm run dev
```

5. Открой сайт:

```text
http://localhost:5173
```

Vite обслуживает интерфейс, а Express API работает на `http://localhost:3001`. Запросы `/api` автоматически проксируются на backend.

### Первый вход

При первом запуске создаётся администратор и демонстрационные данные.

| Поле | Значение по умолчанию |
|---|---|
| Email | `admin@nexora.local` |
| Пароль | `Nexora2026!` |
| Роль | Администратор |

Учётные данные также выводятся в терминал при первом создании администратора. Можно изменить `ADMIN_NAME`, `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env` **до первого запуска**.

> Важно: пароль из `.env` применяется только при создании первого администратора. Если база уже существует, изменение `.env` не перезапишет пароль сохранённого пользователя. Не используй демонстрационный пароль на публично доступном сервере.

## 🏗️ Production-сборка

Собери frontend:

```powershell
npm run build
```

Если папка `dist` существует, Express будет отдавать и API, и собранный интерфейс. Запусти сервер:

```powershell
npm start
```

По умолчанию приложение будет доступно на `http://localhost:3001`. Порт можно изменить через `PORT` в `.env`.

## ⚙️ Настройки `.env`

```env
PORT=3001
NODE_ENV=development
ADMIN_NAME=Alex Morgan
ADMIN_EMAIL=admin@nexora.local
ADMIN_PASSWORD=Nexora2026!
DB_FILE=./data/nexora.sqlite
```

- `PORT` — порт Express API / production-сервера.
- `NODE_ENV=production` включает production-режим и флаг `Secure` для cookie. Используй его за HTTPS.
- `ADMIN_*` — данные первого администратора.
- `DB_FILE` — расположение SQLite-файла относительно корня проекта (можно указать абсолютный путь).

## 🔌 Основные API-маршруты

| Метод | Endpoint | Назначение |
|---|---|---|
| `POST` | `/api/auth/login` | Вход |
| `POST` | `/api/auth/logout` | Выход |
| `GET` | `/api/auth/me` | Текущий пользователь |
| `GET` | `/api/dashboard` | KPI и активность |
| `GET / POST` | `/api/contacts` | Список и создание контактов |
| `PUT / DELETE` | `/api/contacts/:id` | Изменение и удаление контакта |
| `GET / POST` | `/api/deals` | Список и создание сделок |
| `PATCH / DELETE` | `/api/deals/:id` | Этап / изменение и удаление сделки |
| `GET / POST` | `/api/tasks` | Список и создание задач |
| `PATCH / DELETE` | `/api/tasks/:id` | Изменение статуса и удаление задачи |
| `GET` | `/api/reports` | Данные аналитики |
| `GET / POST` | `/api/team` | Просмотр и создание сотрудников (по роли) |
| `PATCH` | `/api/team/:id` | Изменение статуса / роли сотрудника (администратор) |
| `GET` | `/api/health` | Проверка доступности API |

Все маршруты, кроме входа и health-check, требуют авторизованную сессию.

## 🔐 Безопасность и ограничения демо-версии

- Пароли хранятся в виде bcrypt-хешей, а не в открытом виде.
- Сессии представлены случайными токенами; в базе хранится только SHA-256-хеш токена.
- Cookie имеет флаги `HttpOnly` и `SameSite=Lax`; в production добавляется `Secure`. CSP разрешает только локальные скрипты и WebAssembly-компиляцию, необходимую SQLite WASM-драйверу.
- Доступ к разделу команды ограничен ролями на backend, а не только скрытием кнопок в интерфейсе.
- SQL-запросы используют параметры, пользовательский ввод ограничивается по длине.
- SQLite-файл хранит локальные демонстрационные данные. Для production нужны HTTPS, секреты окружения, резервное копирование, мониторинг, политика хранения данных, защита от перебора паролей и полноценный процесс миграций.
- Это первая версия: нет интеграций с почтой, телефонией, платёжными сервисами и внешними календарями. Также пока нет UI для смены собственного пароля и управления профилем.
